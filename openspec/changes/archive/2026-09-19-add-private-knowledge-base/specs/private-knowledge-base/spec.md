## Purpose

让用户能够把自己的 PDF、DOCX 或 Markdown 资料安全地建成个人知识库，并在后续学习中持续检索、管理和复用这些资料。

## ADDED Requirements

### Requirement: 用户可以上传受支持的学习文档

系统 SHALL 允许已登录用户上传 PDF、DOCX 和 Markdown 文档，并在成功处理后返回文档 ID、原始文件名、文件大小、切片数量、状态和创建时间。

#### Scenario: 上传受支持文档并完成索引
- **WHEN** 已登录用户上传内容可读取且扩展名为 PDF、DOCX 或 Markdown 的文件
- **THEN** 系统保存文件、解析文本、建立该用户专属向量索引，并返回状态为 `ready` 的文档元数据

#### Scenario: 拒绝不支持的文件
- **WHEN** 用户上传不属于 PDF、DOCX 或 Markdown 的文件
- **THEN** 系统返回明确的参数错误，不保存文件、不建立向量、不创建可见文档记录

#### Scenario: 拒绝超出大小限制或无法解析的文件
- **WHEN** 文件超过配置的大小上限，或文件内容无法被对应解析器读取
- **THEN** 系统返回稳定的错误状态，并清理本次上传产生的临时文件、索引和数据库记录

### Requirement: 文档内容必须按用户隔离保存和检索

系统 SHALL 将每个文档及其向量归属于上传用户；任何检索、列表、删除和详情操作 MUST 使用当前认证用户身份作为边界。

#### Scenario: 用户检索自己的文档
- **WHEN** 用户用与自己资料相关的查询检索知识库
- **THEN** 系统只返回该用户已上传文档的片段及其文档标识、文件名和页码等来源信息

#### Scenario: 用户不能读取或删除他人文档
- **WHEN** 用户请求另一个用户的文档 ID 或试图通过查询绕过文档归属
- **THEN** 系统按不存在处理或返回无权限错误，不暴露他人文件名、内容、向量或存储路径

#### Scenario: 服务重启后索引仍可用
- **WHEN** 后端重启后用户继续查询自己的知识库
- **THEN** 系统从持久化存储恢复文档元数据和向量索引，无需重新上传

### Requirement: 用户可以查看和删除自己的文档

系统 SHALL 提供当前用户文档列表和删除能力；删除操作 MUST 同步移除原始文件、文档元数据和对应向量。

#### Scenario: 查看文档列表
- **WHEN** 已登录用户请求知识库文档列表
- **THEN** 系统仅返回该用户的文档，按创建时间倒序，并包含处理状态和切片数量

#### Scenario: 删除已就绪文档
- **WHEN** 用户删除自己已建立索引的文档
- **THEN** 系统删除该文档的向量和文件，并使其不再出现在列表或检索结果中

#### Scenario: 重复删除或删除未知文档
- **WHEN** 用户删除已删除或不存在的文档 ID
- **THEN** 系统返回稳定的不存在结果，不删除其他文档，也不泄露路径或内部异常

### Requirement: 敏感配置和文件内容不得泄露

系统 SHALL 只在后端使用 Embedding 服务凭证；错误响应和日志 MUST 不包含 API 密钥、完整文件内容、用户凭证或内部绝对路径。

#### Scenario: Embedding 配置缺失
- **WHEN** 用户上传文档但后端未配置 Embedding 凭证
- **THEN** 系统返回可识别的配置错误，且不把凭证字段或上游响应原文返回给客户端

#### Scenario: 处理失败回滚
- **WHEN** 解析、切分、Embedding 或向量写入任一步骤失败
- **THEN** 系统回滚本次文档的可见状态和已写入资源，并记录不含敏感内容的错误类别
