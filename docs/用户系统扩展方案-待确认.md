## 1. 已确认的范围与依据

- 支持微信小程序和 H5 正式登录，采用账号密码注册登录、微信快捷登录与绑定，两端共享同一用户的数据。
- 使用 MySQL 作为正式数据库。
- 本次包含个人资料、学习记录与历史报告、未完成闯关续答、错题本和基础学习统计。
- 本次不做收藏、签到、勋章、排行榜；文档里的支付、RAG、多源解析、分享海报也不自动纳入此次开发。
- 允许补充新页面原型，复用现有 CSS 视觉语言；底部导航为“闯关 / 学习记录 / 我的”。先审阅原型和开发步骤，再开发。
- 已完整阅读 `docs/需求分析文档.md`、`docs/方案设计文档.md` 和 `mvp-core-sketch-v2.html`，并查看本次提供的参考图片。旧文档中“用户系统不纳入 MVP”是历史阶段边界，本次按上述新要求扩展。原文中的示例提示词、操作指令不作为本次执行授权。

## 2. 当前实现与扩展影响

现有技术栈为 Taro 4.2.1、React 18、TypeScript、FastAPI、Pydantic、LangChain。保留这些技术，不因增加账号功能更换框架。

- 已有首页、答题与反馈、复盘三个页面，六种主要状态。原型使用米白横线纸、黄色按钮、蓝色强调、黑色粗描边及偏移阴影，继续保留。
- 后端仅提供健康检查、生成题库、生成报告三个接口，没有数据库、用户身份或数据归属校验。
- 前端用公共的 `quiz`、`records` 本地存储键保存当前一轮数据；重新进入答题页会从第 1 题初始化，尚无真正的历史列表和续答。
- 报告由服务端按客户端提交的题目、答案和作答记录计算，是确定性统计总结，当前未调用 AI 报告链。本次保存、回看现有类型的报告，不另外引入跨历史 AI 深度分析。
- XP 为本轮答对数乘以 20，尚未与用户累计数据关联。

扩展时，后端必须先保存生成的题库，以服务端保存的标准答案为依据判题、计算 XP 和统计；不能信任客户端回传的标准答案、正确率或用户 ID。

## 3. 建议的产品规则（请与原型一起确认）

### 3.1 注册、登录与绑定

1. 首页可以浏览和输入；生成题目、访问个人学习数据前需要登录。登录后返回原操作，保留已输入的主题。不引入游客记录合并。
2. 两端均提供账号密码登录和注册。账号建议为 4–24 位英文字母、数字、下划线，大小写视为同一账号；密码 8–64 位，注册时输入两次；账号注册后不改名，昵称可改。
3. 小程序另有“微信快捷登录”；H5 使用账号密码，不显示无法在普通浏览器执行的小程序微信登录按钮。
4. 微信已绑定账号：直接登录该账号。微信未绑定：进入“绑定已有账号 / 注册并绑定”页面，验证账号密码后绑定或完成注册。此时不提前创建一个独立用户，避免同一个人出现两套记录。
5. H5 注册用户可在小程序中使用账号密码登录，再从“账号设置”绑定微信。微信入口注册的用户同时拥有账号密码，可直接在 H5 登录。
6. 绑定需要当前账号认证和新的微信身份凭证。微信已属于其他账号时，明确提示冲突，不自动合并、覆盖或转移学习数据。本轮不做微信解绑和自助账号合并。
7. 提供已登录状态下的修改密码（验证原密码），修改后使各端旧登录态失效，要求重新登录。退出登录仅撤销当前会话，并清理本账号本地缓存。
8. 登录态绝对有效期建议 7 天，到期重新登录；允许两端同时登录。所有业务请求都以服务端会话确认用户。
9. 本轮不接短信/邮件验证码和忘记密码自助找回。已绑定微信的用户仍可微信登录；密码找回或重置另行确定身份核验方案，不提供无核验重置入口。

### 3.2 个人资料与账号设置

- “我的”：头像、昵称、累计 XP、已完成闯关数、累计答题数、正确率，以及错题本、编辑资料、账号设置入口。
- 昵称建议 1–20 字，不强制用户更换默认昵称或头像才能学习。
- 小程序头像选择使用 `chooseAvatar`，昵称使用 `type=nickname` 对应的填写能力；H5 使用图片选择和普通文本输入。
- 头像临时文件上传后才作为长期资料保存；服务端校验实际文件格式、大小（建议最多 2 MB，仅 JPEG/PNG/WebP），重新编码，使用服务器生成的文件名。不把临时本地路径当作永久图片地址。
- 两端保存成功后刷新展示；退出和切换账号时清空上一账号的资料及学习缓存。

### 3.3 学习记录、续答与报告

- 列表按最近学习时间排序，支持“全部 / 未完成 / 已完成”，分页加载；显示主题、题量、进度或正确率、日期。
- 生成题库即归属于当前用户，创建一轮学习记录。每题提交后保存作答，列表可继续这一轮，进入尚未作答的题目。
- 先本地展示原有即时对错与讲解，同时请求后端保存和复核；保存失败显示“尚未同步”，允许重试，保存成功后才进入下一题。退出前有未保存内容时提示。短时重试数据按用户和本轮 ID 隔离，跨端只能恢复服务端已确认的数据。
- 同一题首次作答一经保存不能改写。重复相同提交返回已有结果；提交不同答案返回冲突并恢复服务端记录。用于防止多端同时答题、重试和连点重复记分。
- 完成所有题目才结算这一轮；报告、XP 结算和完成状态保持事务一致。重新打开报告或重复请求不会再次结算。
- 报告保留当时的题目、作答、正确率、总结和薄弱点。历史报告直接读取已保存内容，并可回看每题选项及解析。
- 已完成的一轮不覆盖历史结果。“再闯一轮”保留现有重新出题的含义，生成新的独立记录；不额外做整套旧题无限刷分入口。
- 本轮不提供学习记录删除，不把旧的匿名本地记录自动认领为新账号正式成绩。旧数据没有可靠的用户归属及服务端标准题库，不能直接参与账户统计。

### 3.4 错题本与复习

- 服务端确认答错后自动入错题本。唯一性按“用户 + 原题库 ID + 题目 ID”判断，重试不产生重复错题；不同生成题库不做语义去重。
- 显示原题干、来源主题、我的答案、正确答案、解析和复习状态，支持“待复习 / 已掌握”筛选。
- 可复习单题或按最近答错顺序开始最多 5 题的一组复习，复用已有答题/反馈样式。
- 复习答对即标为“已掌握”，答错保留“待复习”。错题本保留已掌握记录，可再次查看或复习。原始报告的对错不因复习改变。
- 复习有独立的作答记录，支持未完成续答；其结果不增加累计 XP，也不混入普通闯关正确率。暂不加入遗忘曲线、复习通知或复杂推荐。

### 3.5 统计和 XP

- 普通闯关每道首次答对 20 XP，答错 0 XP，整轮完成后一次性计入累计 XP；未完成的一轮显示本轮已得 XP，但不计入账户累计。
- 完成闯关数、累计答题数、累计正确率和累计学习用时，仅统计已完成的普通闯关。正确率为总答对题数除以总题数，不平均各轮百分比。
- “待复习错题数”按尚未掌握的错题计算，与历史答错总数区别展示。
- 使用 Asia/Shanghai 作为用户日期展示和每日汇总口径，服务端保存 UTC 时间。基础统计不额外生成 AI 知识树或分析报告。
- 学习用时由客户端记录实际答题时间，暂停/切到后台时不累计；服务端验证范围。此数据仅用于个人复盘，不作为竞赛或奖励依据。

- 原有首页：保持输入框、气泡、吉祥物、标签及按钮结构，增加底部 Tabbar；继续入口放在学习记录。
- 登录、注册、首次微信绑定：复用纸张、描边输入框和黄色主按钮。
- 学习记录：状态筛选、记录卡片、进度、继续答题/查看报告入口。
- 我的：头像昵称卡、统计便签、错题本和账号设置入口。
- 编辑资料与账号设置：头像昵称编辑、微信绑定状态、密码修改及退出登录。

## 5. 技术方案

### 5.1 后端与身份

保留 FastAPI 同步服务方式，新增 SQLAlchemy 2.x、PyMySQL、Alembic。生产和集成测试使用 MySQL，不以 SQLite 通过替代 MySQL 验证；模型相关接口继续复用当前 LangChain 出题逻辑。

密码用 Argon2 哈希保存。推荐采用服务端可撤销会话：随机令牌只在客户端持有，数据库保存其摘要、用户、到期时间和撤销状态，避免引入 JWT 刷新与黑名单的额外链路。

- 小程序：通过 Authorization Bearer 发送会话令牌。
- H5：使用 HttpOnly、Secure、SameSite Cookie；生产推荐 H5 与 `/api` 同源部署。所有 Cookie 身份的写接口检查可信 Origin 和 CSRF 凭证；开发代理同源转发，不开放携带凭证的通配 CORS。
- 身份依赖统一取得当前用户，数据查询必须带用户归属条件。无登录返回 401；他人数据按不存在处理，避免泄露内容。
- 登录失败文案统一，不在日志或错误响应中回传密码、会话、微信凭证或数据库连接串。注册和登录加入有限的失败尝试限制，保证多进程下口径一致。
- 微信登录调用 `Taro.login` 取得一次性 code，后端访问 `code2Session` 换取身份，再生成自有登录态。AppSecret 只保留在服务端环境变量中；session_key 不下发。
- 未绑定微信的临时绑定票据建议有效期 5 分钟、一次性消费，并绑定微信身份。注册/绑定在事务中检查账号及微信唯一约束。

### 5.2 数据模型（建议）

| 表 | 用途与关键约束 |
| --- | --- |
| users | 账号、密码哈希、昵称、头像存储键、可空的唯一微信 OpenID；账号规范化唯一 |
| user_sessions | 会话摘要、用户、到期时间、撤销时间 |
| wechat_binding_tickets | 临时票据摘要、微信身份、到期/消费状态 |
| auth_throttles | 登录/注册失败尝试窗口，供多实例一致限流 |
| quizzes | 用户、主题、普通/复习类型、不可变题目 JSON；复习题保留原题来源引用 |
| learning_attempts | 用户、题库、开始/更新时间、进行中/已完成、最终得分与 XP |
| answers | 本轮题目、首次选择、服务端对错、用时；本轮+题目唯一 |
| reports | 一轮唯一的统计与总结快照 |
| wrong_questions | 用户、原题库+题目、状态、最近复习时间；来源唯一 |

普通练习和错题复习复用学习轮次与答案表，通过类型区分统计；不另造一套答题引擎。所有状态结算使用事务及唯一约束；并发提交和结束通过 MySQL 行锁/条件更新处理。跨 AI 网络调用不持有数据库行锁。

### 5.3 接口分组（路径在实现计划中最终固定）

| 分组 | 拟提供能力 |
| --- | --- |
| `/api/v1/auth/*` | 注册、密码登录、微信登录、首次绑定完成、已登录绑定、退出、修改密码 |
| `/api/v1/users/me` | 读取/编辑个人资料、上传头像、读取基础统计 |
| `/api/v1/quiz/generate` | 登录后生成并保存题库、返回学习轮次 |
| `/api/v1/attempts/*` | 分页学习记录、详情、提交单题、恢复进度、完成结算、读取历史报告 |
| `/api/v1/wrong-questions/*` | 错题列表、详情、创建复习轮次 |

原 `report/generate` 接口调整为引用服务端学习轮次，不再接受客户端题库作为正式结算依据；前后端一并更新。统一保留 `{code, message, data}` 响应结构。参数错误、未登录、不存在、冲突、限流分别定义明确状态码与前端提示。

### TDD 执行要求

所有新增或变更的后端行为按“写失败测试 → 运行确认预期失败 → 最少实现 → 运行通过 → 必要整理”进行，并记录每个功能批次的红绿结果。不能完成业务后再一次性补测试。

测试使用真实应用、真实服务层和专用 MySQL 测试库；仅在外部 HTTP 边界模拟微信与大模型。核心数据库集成测试至少覆盖：

1. 注册重复/大小写冲突、密码校验、错误登录、会话到期/撤销、改密撤销各端登录、CSRF 与账号隔离。
2. 微信 code 失败/超时、已绑定登录、首次绑定票据到期/重放、微信身份已占用、并发绑定。
3. 昵称边界、头像格式/大小/路径、写入失败处理、资料不可越权。
4. 出题归属、生成失败无半成品记录、进度恢复、未知题目、重复/冲突作答、不完整结算、并发完成、服务端评分。
5. 错题去重、答对转为已掌握、复习中断恢复、历史报告保持不变、复习不累计 XP。
6. 零记录统计、不同题量的加权正确率、只统计完成轮次、时区边界、所有历史/报告/复习查询的越权拒绝。
