# 用户系统开发与运行说明

本次实现依据《用户系统方案设计文档-最终版》：微信静默登录、JWT 强制鉴权、四表持久化、档案与统计、完成历史和三栏 TabBar。没有游客、续答、逐题落库或额外通关奖励。

## 后端启动

项目原有 `.venv` 无法启动，已保留并新建 `.venv-user`。Windows PowerShell 从项目根目录执行：

```powershell
Set-Location backend
..\.venv-user\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

本地配置保存在忽略提交的 `backend/.env`，字段参考 `backend/.env.example`。JWT 签名密钥已在本地随机生成；替换密钥会使现有登录态失效。前端与后端使用相同的小程序 AppID，AppSecret 和模型密钥只保留在后端。

新机器可创建 Python 虚拟环境后安装 `backend/requirements.txt`。本次验证环境为 Python 3.14.6、MySQL 8.0.45；MySQL 需预先按 `sql/001_user_system.sql` 初始化。应用启动只连接数据库，不自动建表或清空数据。

## 测试

先从项目根目录执行一次专用测试库初始化：

```powershell
.\.venv-user\Scripts\python.exe backend/tests/prepare_mysql.py
```

该脚本只读取业务库表结构；创建并初始化独立 `yu_ai_learn_test`。自动化测试会清理这个固定测试库中的四表，绝不清理 `yu_ai_learn`。不要将实际业务数据放入测试库，也不要同时启动两组后端测试。

```powershell
Set-Location backend
..\.venv-user\Scripts\python.exe -m pytest -q --tb=line --cov=app --cov-report=term-missing
```

测试使用真实 MySQL 连接、唯一约束、外键、事务和并发请求。微信与模型的外部 HTTP 在自动化测试中使用受控响应；这与后续真实微信联调分开记录。

`tests/smoke_deepseek.py` 仅检查实际模型出题服务，不是登录或持久化的完整验证。需要运行时，在 backend 目录执行：

```powershell
$env:PYTHONPATH = '.'
..\.venv-user\Scripts\python.exe tests/smoke_deepseek.py
```

## 前端与微信

在 `frontend` 目录执行 `npm run build:weapp`，然后将 `frontend` 导入微信开发者工具（小程序目录为 `dist/`）。默认开发 API 地址为 `http://localhost:8000`，可通过前端本地环境变量 `TARO_APP_API_BASE_URL` 调整。真机不能访问电脑的 localhost，需使用可达的 HTTPS 后端及小程序合法域名配置。

H5 构建只用于界面预览，不提供正式登录与答题。正式验收在微信端完成；编译成功与模拟器验证均不能替代物理手机真机验收。

## 数据与兼容性

- 原出题请求/题库返回结构保留，新增登录校验和落库；模型结构化输出、去重和质量重试不变。
- 原报告请求字段保留，但判题只使用数据库中的题库；客户端提交的对错与标准答案不影响结算。
- 每道正确题 20 XP，整轮只结算一次。重复请求返回首次报告。
- 结算先锁定题库，再更新用户 XP，最后写答案和报告，同一事务提交；这个顺序避免同用户不同轮次因外键共享锁升级而死锁。
- 历史仅包含完成轮次，统计正确率为累计正确数除以累计题数。
- 中途退出后不恢复题目；完成整轮但提交失败时保留待提交数据，同账号重登可重试，换账号清理。
- 前端是原工作区中的独立 Git 仓库。本次不自动 commit 或 push；提交时需分别检查根仓库和 frontend 的改动。
